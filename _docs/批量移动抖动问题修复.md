# 批量移动抖动问题修复

## 问题日期
2026-01-29

## 问题描述

批量移动多个节点时，节点会出现"闪回旧位置再闪回新位置"的抖动现象。这个问题在之前已经修复过（见 `DEBUG_SESSION_SUMMARY.md`），但又重新出现了。

## 调试过程

### 生成的假设

通过系统的日志分析，生成了以下调试假设：

- **H1**: 服务器回显导致位置闪回
- **H2**: `handleNodeDataUpdate` 的 position 更新冲突
- **H3**: ✅ **CONFIRMED** - 节点签名检查触发重新初始化
- **H4**: 批量更新时部分节点的 `draggingNodesRef` 状态不正确
- **H5**: `snapPositionRef` 缓存导致位置不一致

### 关键日志证据

通过运行时日志，发现了问题的根本原因（H3）：

```json
{"location":"InfiniteCanvas.tsx:426","message":"initialNodes effect check","data":{"signatureChanged":true,"initialized":true,"nodesCount":13}}
{"location":"InfiniteCanvas.tsx:438","message":"Reinitializing nodes","data":{"nodesCount":13,"firstNodePos":{"x":922.625...}}}
```

**证据链：**

1. 拖动期间，每次位置更新都触发 `signatureChanged: true`
2. 这导致 `Reinitializing nodes` 被频繁调用
3. 节点被重置到 `initialNodes` 中的旧位置
4. 服务器回显的旧位置数据也到达，加剧了抖动
5. 节点在新旧位置之间反复跳动

## 根本原因

### 问题代码

在 `InfiniteCanvas.tsx` 中，节点签名的计算方式包含了**所有节点属性**：

```typescript
// ❌ 问题代码
const nodeSignature = initialNodes
  .map((node) => JSON.stringify(node))  // 包含 position！
  .sort()
  .join('|');
```

**问题流程：**

1. 用户拖动节点 → 本地位置更新
2. 位置更新传递到 `CollaborativeCanvas` → 更新 `nodes` state
3. 新的 `nodes` 作为 `initialNodes` prop 传递给 `InfiniteCanvas`
4. `InfiniteCanvas` 检测到签名变化（因为 `position` 改变了）
5. **触发重新初始化** → 节点被重置到 `initialNodes` 中的位置
6. 造成节点在新旧位置之间反复跳动

### 为什么这是个问题

节点签名应该只用于检测**结构性变化**（添加/删除节点、改变类型），而不应该包含**动态属性**（如 position）。当动态属性变化时触发重新初始化会导致：

- 拖动时的位置更新被重置
- 性能问题（频繁重新初始化）
- 与服务器回显的位置数据冲突

## 解决方案

### 修复代码

修改签名计算，只包含结构性属性：

```typescript
// ✅ 修复后
const nodeSignature = initialNodes
  .map((node) => `${node.id}:${node.type}:${node.size.width}:${node.size.height}`)
  .sort()
  .join('|');
```

### 修复文件

- `packages/widget/src/InfiniteCanvas.tsx`

### 关键变更

**修复前：**
```typescript
// 包含所有属性（包括 position、zIndex 等动态属性）
const nodeSignature = initialNodes
  .map((node) => JSON.stringify(node))
  .sort()
  .join('|');
```

**修复后：**
```typescript
// 只包含结构性属性
// 计算节点结构签名，只包含节点ID、类型等结构性属性，排除position等动态属性
// 这样可以避免在拖动时因position变化而触发重新初始化
const nodeSignature = initialNodes
  .map((node) => `${node.id}:${node.type}:${node.size.width}:${node.size.height}`)
  .sort()
  .join('|');
```

## 技术要点

### 签名检查的目的

节点签名检查的目的是：
- 检测节点的**结构性变化**（添加/删除节点）
- 检测节点的**类型变化**
- 检测节点的**尺寸变化**（需要重新布局）

### 不应该包含的属性

以下属性是**动态的**，不应该包含在签名中：
- `position` - 拖动时频繁变化
- `zIndex` - 选中/取消选中时可能变化
- `selected` - UI 状态
- `dragging` - UI 状态
- 其他仅用于渲染的临时状态

### 应该包含的属性

以下属性是**结构性的**，应该包含在签名中：
- `id` - 节点唯一标识
- `type` - 节点类型（image/video/audio/text）
- `size.width` / `size.height` - 节点尺寸（影响布局）

## 验证结果

修复后，批量移动节点时：
- ✅ 节点平滑移动，没有抖动
- ✅ 不再触发频繁的重新初始化
- ✅ 拖动期间 `signatureChanged` 保持 `false`
- ✅ 只有真正的结构变化才会触发重新初始化

## 经验教训

1. **签名检查要精确**：只包含真正需要检测变化的属性
2. **区分结构性和动态属性**：结构性属性用于签名，动态属性用于渲染
3. **避免过度重新初始化**：频繁的重新初始化会导致性能问题和状态丢失
4. **使用运行时日志调试**：通过日志分析可以快速定位问题根源
5. **关注 effect 的依赖**：确保 effect 只在必要时触发

## 总结

通过修改节点签名的计算方式，从包含所有属性改为只包含结构性属性，成功解决了批量移动时的抖动问题。这个修复不仅解决了当前的问题，还提升了整体性能，因为减少了不必要的重新初始化。
