# 房间列表问题排查和修复指南

## 快速诊断

如果管理面板的房间列表为空或缺少房间,按以下步骤排查:

### 1. 检查系统健康状态

```bash
# 检查系统健康状态
curl https://infinite-canvas-collab-server.buzzbus.workers.dev/health
```

**预期输出**:
```json
{
  "status": "healthy",
  "timestamp": 1706000000000,
  "checks": {
    "d1": { "status": "ok", "latency": 15 },
    "r2": { "status": "ok", "latency": 8 }
  },
  "latency": 25
}
```

**如果 D1 状态为 error**:
- 检查 D1 数据库配置
- 查看 Worker 日志确认错误详情
- 确认 D1 数据库已正确初始化

### 2. 检查 D1 数据库内容

```bash
# 查看数据库列表
wrangler d1 list

# 查看 canvases 表内容
wrangler d1 execute canvas_db --command "SELECT * FROM canvases ORDER BY updated_at DESC LIMIT 10"

# 检查表结构
wrangler d1 execute canvas_db --command "SELECT sql FROM sqlite_master WHERE type='table' AND name='canvases'"
```

**如果表为空**:
- 说明 D1 记录创建失败
- 继续下一步查看 Worker 日志

**如果表不存在**:
- 需要初始化数据库 schema
- 运行: `wrangler d1 execute canvas_db --file=./d1/schema.sql`

### 3. 查看 Worker 日志

```bash
# 实时查看日志
wrangler tail

# 或在 Cloudflare Dashboard 中查看日志
# https://dash.cloudflare.com -> Workers & Pages -> 选择 worker -> Logs
```

**关键日志搜索**:
- `❌ Error ensuring D1 record` - D1 写入失败
- `✅ Created D1 record` - D1 记录创建成功
- `Failed to ensure D1 record` - D1 写入重试失败
- `D1 record attempt` - 重试过程

### 4. 检查特定房间状态

```bash
# 查看房间状态 (需要知道 roomId)
curl -H "Authorization: Bearer user_admin" \
  https://infinite-canvas-collab-server.buzzbus.workers.dev/admin/rooms/{roomId}
```

**预期输出**:
```json
{
  "roomId": "demo",
  "seq": 42,
  "nodeCount": 10,
  "activeConnections": 2,
  "metrics": {
    "d1RecordEnsured": true,
    "d1WriteAttempts": 3,
    "d1WriteFailures": 0,
    "d1WriteSuccessRate": "100.00%"
  }
}
```

**关键指标**:
- `d1RecordEnsured: false` - D1 记录未创建
- `d1WriteFailures > 0` - 有写入失败
- `d1WriteSuccessRate < 100%` - 写入成功率低

## 修复方案

### 方案 1: 为单个房间创建 D1 记录

**适用场景**: 知道具体的房间 ID,需要手动添加到列表

**步骤**:

1. **确认房间 ID**
   - 从 URL 中获取: `?canvasId=xxx`
   - 或从应用日志中查找

2. **调用修复 API**
   ```bash
   curl -X POST \
     -H "Authorization: Bearer user_admin" \
     -H "Content-Type: application/json" \
     -d '{"roomId": "demo"}' \
     https://infinite-canvas-collab-server.buzzbus.workers.dev/admin/rooms/create-record
   ```

3. **验证结果**
   ```json
   {
     "success": true,
     "action": "created",  // 或 "updated"
     "roomId": "demo",
     "seq": 42,
     "nodeCount": 10
   }
   ```

4. **刷新管理面板**
   - 房间应该立即出现在列表中

### 方案 2: 批量扫描并修复所有房间

**适用场景**: 需要修复所有缺失的 D1 记录

**步骤**:

1. **运行批量扫描**
   ```bash
   curl -X POST \
     -H "Authorization: Bearer user_admin" \
     https://infinite-canvas-collab-server.buzzbus.workers.dev/admin/rooms/scan-and-fix
   ```

2. **查看修复结果**
   ```json
   {
     "success": true,
     "summary": {
       "total": 15,
       "created": 10,
       "updated": 0,
       "skipped": 3,
       "failed": 2
     },
     "results": [
       { "roomId": "room1", "action": "created", "seq": 10 },
       { "roomId": "room2", "action": "skipped" },
       { "roomId": "room3", "action": "failed", "error": "D1 insert failed" }
     ]
   }
   ```

3. **处理失败的房间**
   - 查看失败原因
   - 使用方案 1 单独修复

### 方案 3: 初始化 D1 数据库

**适用场景**: D1 表不存在或结构错误

**步骤**:

1. **备份现有数据** (如果有)
   ```bash
   wrangler d1 execute canvas_db --command "SELECT * FROM canvases" > backup.json
   ```

2. **删除旧表** (可选)
   ```bash
   wrangler d1 execute canvas_db --command "DROP TABLE IF EXISTS canvases"
   ```

3. **创建新表**
   ```bash
   wrangler d1 execute canvas_db --file=./packages/server/d1/schema.sql
   ```

4. **验证表结构**
   ```bash
   wrangler d1 execute canvas_db --command "SELECT sql FROM sqlite_master WHERE type='table' AND name='canvases'"
   ```

5. **运行批量修复**
   - 使用方案 2 重新创建所有房间记录

## 常见问题

### Q1: 为什么新创建的房间不出现在列表中?

**可能原因**:
1. D1 写入失败但被静默处理
2. DO 在 D1 记录创建前被销毁
3. D1 数据库权限问题

**解决方法**:
1. 查看 Worker 日志确认错误
2. 使用方案 1 手动创建记录
3. 检查 D1 数据库配置和权限

### Q2: R2 中为什么没有新数据?

**答案**: 这是正常的!

R2 存储已被废弃,系统已切换到 DO Storage 模式:
- 1月23日之前: 使用 R2 快照模式
- 1月23日之后: 使用 DO Storage 模式
- 所有新数据都在 DO Storage 中,不在 R2 中

R2 现在只用于:
- 读取历史数据 (迁移用)
- 删除操作时清理历史快照

### Q3: 如何查看 DO Storage 中的数据?

**答案**: DO Storage 无法直接查看,但可以通过以下方式间接查看:

1. **通过管理 API**
   ```bash
   curl -H "Authorization: Bearer user_admin" \
     https://infinite-canvas-collab-server.buzzbus.workers.dev/admin/rooms/{roomId}
   ```

2. **通过 D1 数据库**
   ```bash
   wrangler d1 execute canvas_db --command "SELECT * FROM canvases WHERE id = '{roomId}'"
   ```

3. **连接到画布查看**
   - 打开画布页面
   - DO 会自动从 DO Storage 加载数据

### Q4: D1 写入成功率低怎么办?

**排查步骤**:

1. **查看房间状态中的指标**
   ```bash
   curl -H "Authorization: Bearer user_admin" \
     https://infinite-canvas-collab-server.buzzbus.workers.dev/admin/rooms/{roomId}
   ```

2. **检查日志中的错误**
   ```bash
   wrangler tail | grep "Error ensuring D1 record"
   ```

3. **常见错误及解决方法**:
   - `D1 insert failed`: 检查表结构和约束
   - `Timeout`: D1 响应慢,增加重试次数
   - `Permission denied`: 检查 D1 绑定和权限

### Q5: 批量修复时部分房间失败怎么办?

**解决方法**:

1. **查看失败原因**
   - 批量修复 API 会返回每个房间的详细结果
   - 重点关注 `action: "failed"` 的房间

2. **单独修复失败的房间**
   ```bash
   # 对每个失败的房间单独调用
   curl -X POST \
     -H "Authorization: Bearer user_admin" \
     -H "Content-Type: application/json" \
     -d '{"roomId": "failed_room_id"}' \
     https://infinite-canvas-collab-server.buzzbus.workers.dev/admin/rooms/create-record
   ```

3. **如果持续失败**
   - 检查该房间的 DO 状态
   - 查看 Worker 日志
   - 可能需要重建该房间

## 预防措施

### 1. 定期监控

**设置监控告警**:
- 监控 `/health` 端点
- 定期检查 D1 写入成功率
- 关注 Worker 日志中的错误

**监控脚本示例**:
```bash
#!/bin/bash
# health-check.sh

HEALTH_URL="https://infinite-canvas-collab-server.buzzbus.workers.dev/health"

response=$(curl -s $HEALTH_URL)
status=$(echo $response | jq -r '.status')

if [ "$status" != "healthy" ]; then
  echo "❌ System unhealthy: $response"
  # 发送告警通知
else
  echo "✅ System healthy"
fi
```

### 2. 定期备份

**备份 D1 数据库**:
```bash
#!/bin/bash
# backup-d1.sh

DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_FILE="backup_${DATE}.json"

wrangler d1 execute canvas_db \
  --command "SELECT * FROM canvases" \
  > $BACKUP_FILE

echo "Backup saved to $BACKUP_FILE"
```

### 3. 日志分析

**定期分析日志**:
```bash
# 统计 D1 写入失败次数
wrangler tail --format json | jq 'select(.message | contains("Error ensuring D1 record"))'

# 统计成功创建的房间
wrangler tail --format json | jq 'select(.message | contains("Created D1 record"))'
```

## 故障排除流程图

```
房间列表为空
    ↓
检查系统健康 (/health)
    ↓
D1 状态是否正常?
    ├─ 否 → 检查 D1 配置和权限 → 初始化数据库
    └─ 是 ↓
查看 D1 表内容
    ↓
表是否为空?
    ├─ 是 → 运行批量修复 (scan-and-fix)
    └─ 否 ↓
查看 Worker 日志
    ↓
有 D1 写入错误?
    ├─ 是 → 修复错误 → 重试
    └─ 否 ↓
检查特定房间状态
    ↓
d1RecordEnsured 是否为 true?
    ├─ 否 → 手动创建记录 (create-record)
    └─ 是 → 问题已解决
```
