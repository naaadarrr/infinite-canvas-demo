# 无限画布迭代 PRD

> **日期**: 2026-03-12  

---

## 一、小项目拆解与重要节点

> 将「无限画布优化」拆成多个小项目，每个项目有明确目标与可验收节点，便于排期与验收。

### 1.1 总览：项目与重要节点数量

> **本次迭代范围**：按「无限画布」持续优化的五大方向推进，**不含多人协作**。多人协作（项目 13）保留在 backlog，待后续排期。

| 维度 | 数量 | 说明 |
|------|------|------|
| **小项目总数** | **14**（本次迭代做 13，协作延后） | 每个可独立排期与验收 |
| **重要节点总数** | **约 49**（本次约 45） | 每个节点可验收、可勾选 |
| **上线前必做** | 项目 1～4（约 18 个节点） | 与 Board UI 统一，保证「同一产品两 view」 |
| **能力与交互** | 项目 5～9（约 26 个节点） | 工具接入、画布交互、多选/右键/快捷操作、动效、无障碍与性能 |
| **上线后/并行** | 项目 10～12、14（约 12 个节点） | 联合优化、图层、历史撤销；**项目 13 多人协作本迭代不做** |

---

### 1.2 小项目清单（含重要节点）

---

#### 项目 1：Board 设计体系接入与 Token 统一

**为什么重要**：两 view 若用两套颜色、字体、圆角，用户会感觉是两个产品；先统一设计 token，后续组件才有依据。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 1.1 | 拿到 Board 代码库路径与设计规范/组件清单 | 文档：仓库路径、token 列表、可复用组件名 |
| 1.2 | 输出「Board 与 Canvas 需对齐的 UI 维度」清单 | 颜色、字体、圆角、间距、阴影、边框等 |
| 1.3 | Canvas 工程接入 Board 设计 token（或复刻一致 token） | 代码：Canvas 使用与 Grid 同一套 token |
| 1.4 | 设计/前端验收：两 view 基础视觉语言一致 | 验收通过 |

**重要节点数**：4

---

#### 项目 2：侧边栏与底部工具栏视觉统一

**为什么重要**：侧边栏和底部栏是用户切换 view 后第一眼看到的框架，必须与 Board（Grid）一致，才能强化「同一产品」感知。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 2.1 | 侧边栏：宽度、背景、图标风格、选中态与 Board 一致 | UI 走查通过 |
| 2.2 | 底部工具栏：高度、圆角、按钮样式、缩放控件与 Board 一致 | UI 走查通过 |
| 2.3 | 工具栏在深色背景下的对比度与可点击性达标 | 设计验收 |

**重要节点数**：3

---

#### 项目 3：Canvas 面板与弹窗视觉统一

**为什么重要**：创作面板（Canvas Panel）和沉浸弹窗（Immersive Modal）是 Canvas 高频界面，风格需与 Board 内其他面板/弹窗一致。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 3.1 | Canvas Panel：背景、边框、圆角、Tab 栏、底部按钮栏与 Board 一致 | UI 走查通过 |
| 3.2 | Immersive Modal：遮罩、标题栏、关闭按钮、内容区与 Board 弹窗一致 | UI 走查通过 |
| 3.3 | 输入框、下拉、主按钮/次按钮等控件与 Board 复用或视觉一致 | 设计验收 |

**重要节点数**：3

---

#### 项目 4：「两 view 同一产品」整体验收

**为什么重要**：单点对齐后，需一次整体验收，确保无遗漏、无割裂感，才能进入上线准备。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 4.1 | 设计/产品走查：Grid 与 Canvas 切换前后视觉与交互语言一致 | 走查报告 + 问题清单 |
| 4.2 | 问题修复与回归 | 所有 P0 问题关闭 |
| 4.3 | 验收：可进入上线准备 | 验收通过 |

**重要节点数**：3

---

#### 项目 5：参考产品交互调研与可借鉴清单

**为什么重要**：细节交互与品质感以 weavy、tapnow、lovart 为参考；先产出清单，后续项目才有依据。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 5.1 | 画布与导航：平移/缩放/选中/多选/框选等可借鉴点（附截图或录屏） | 文档 |
| 5.2 | 节点与快捷操作：悬停/选中/QuickAction/右键/快捷键等可借鉴点 | 文档 |
| 5.3 | 面板与弹窗：打开/关闭动效、焦点、Esc 等可借鉴点 | 文档 |
| 5.4 | 优先级排序：哪些先做、哪些可后续迭代 | 文档 |

**重要节点数**：4

---

#### 项目 6：接入其他小工具（Image / Video / Audio / Avatar）

**为什么重要**：侧栏已有入口，但画布上需完整支持各类素材的占位节点、创作面板与事件桥对接；Image 外，Video / Audio / Avatar 等小工具接入后，Canvas 才能覆盖「多类型创作」场景。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 6.1 | Image 类小工具在 Canvas 的完整链路（占位 → Panel/Modal → 事件桥 → 结果回填） | 功能验收 |
| 6.2 | Video 类小工具在 Canvas 的接入（占位节点、面板/弹窗、与 Grid 数据同步） | 功能验收 |
| 6.3 | Audio 类小工具在 Canvas 的接入 | 功能验收 |
| 6.4 | Avatar（数字人）类小工具在 Canvas 的接入 | 功能验收 |
| 6.5 | 各类型与 Board/Grid 双向同步，无遗漏或重复 | 功能验收 |

**重要节点数**：5

---

#### 项目 7：画布导航与手感（平移、缩放、Space、光标）

**为什么重要**：平移、缩放、Space 临时 Pan、光标与工具栏状态一致，是画布「丝滑」的基础，直接影响第一印象。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 7.1 | 平移/缩放手感优化（含滚轮、触控板、双指） | 体验验收 |
| 7.2 | Space 临时 Pan、松开恢复 Select，光标与底部工具栏状态一致 | 体验验收 |
| 7.3 | 画布与节点光标（grab/grabbing/pointer）符合规范 | 体验验收 |

**重要节点数**：3

---

#### 项目 8：画布基础交互完善（多选、右键、快捷操作）

**为什么重要**：多选/框选、右键菜单、QuickAction 与快捷键是日常高频操作，与 Grid 能力等价且符合 PRD 映射表，是「同一产品两 view」的体验关键。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 8.1 | 多选：⌘/Ctrl 点击、框选（拖拽空白区域）行为与反馈明确 | 功能 + 体验验收 |
| 8.2 | 右键菜单：与 PRD/映射表一致，条目完整、无冲突 | 功能验收 |
| 8.3 | QuickAction 栏：出现/收起时机与动效合理，与参考产品水准对齐 | 体验验收 |
| 8.4 | 快捷键：与 PRD/映射表一致，无缺失或冲突 | 功能验收 |
| 8.5 | 多选状态下 QuickAction 与批量操作（下载、删除等）一致 | 功能验收 |
| 8.6 | 节点悬停/选中态视觉与交互符合规范 | 体验验收 |

**重要节点数**：6

---

#### 项目 9：AI 创作面板与弹窗动效与节奏

**为什么重要**：Canvas Panel 与 Immersive Modal 的打开/关闭、焦点、Esc 行为统一，能显著降低「卡顿感」和误操作。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 9.1 | Canvas Panel 打开/关闭动效（含 Inline 与 Standalone）符合规范 | 体验验收 |
| 9.2 | Immersive Modal 打开/关闭动效与焦点管理符合规范 | 体验验收 |
| 9.3 | Esc、点击外部关闭行为统一，无焦点陷阱 | 体验验收 |
| 9.4 | 与参考产品在「面板出现/消失节奏」上对齐 | 体验验收 |

**重要节点数**：4

---

#### 项目 10：无障碍与性能

**为什么重要**：键盘可操作、焦点可见、大画布下不卡顿，是上线前后都会被关注的质量底线。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 10.1 | 关键流程支持键盘操作，焦点顺序合理、焦点可见 | 无障碍验收 |
| 10.2 | 大画布（如 100+ 节点）下帧率与交互延迟达标 | 性能验收 |
| 10.3 | 首屏与切换 view 的加载时间达标 | 性能验收 |

**重要节点数**：3

---

#### 项目 11：上线后 Board + Canvas 联合优化

**为什么重要**：统一上线后两边 UI 一起优化；需要先建立机制，再按迭代执行。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 11.1 | 建立两 view 反馈收集方式（中台/用户反馈入口） | 机制落地 |
| 11.2 | 输出首版 Board + Canvas 联合优化 backlog（含优先级） | 文档 |
| 11.3 | 对齐首轮联合优化范围与时间 | 排期确认 |

**重要节点数**：3

---

#### 项目 12：图层与层级管理（Layers）

**为什么重要**：底部栏已有 Layers 入口，画布上节点需要「前后顺序、锁定、显隐」等能力，与专业创作工具预期一致。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 12.1 | Layers 面板：节点列表、顺序调整（置顶/置底/上移/下移） | 功能验收 |
| 12.2 | 画布上与 Layers 的联动：选中、定位到节点、锁定/解锁 | 功能验收 |
| 12.3 | 与 Board/Grid 的层级语义一致或可映射 | 产品验收 |

**重要节点数**：3

---

#### 项目 13：协作与 Presence（多人光标、选中态、锁）

**为什么重要**：Canvas 的差异化价值包含「同屏协作可见」；多人光标、他人选中态、编辑锁是协作体验的基础。**本迭代不做，延后排期。**

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 13.1 | 多人实时光标/头像在画布上可见、性能可接受 | 功能 + 性能验收 |
| 13.2 | 他人选中节点态在画布上可见（如高亮或描边） | 功能验收 |
| 13.3 | 编辑锁：某人打开某节点面板时，他人可见「被占用」状态 | 功能验收 |
| 13.4 | 与现有协作层（DO/Board）对接稳定，无冲突 | 技术验收 |

**重要节点数**：4

---

#### 项目 14：历史与撤销（Undo / Redo）

**为什么重要**：创作过程中误操作频繁，Undo/Redo 是基础预期；画布上的移动、删除、创建、参数变更需可撤销。

| 节点序号 | 重要节点 | 产出/验收 |
|----------|----------|-----------|
| 14.1 | 画布操作（节点移动、缩放、删除、创建）支持 Undo/Redo | 功能验收 |
| 14.2 | 快捷键（如 ⌘Z / Ctrl+Z）与 PRD 一致，与输入框等无冲突 | 功能验收 |
| 14.3 | 历史栈与协作冲突策略明确（如 last-write-wins 或提示） | 产品/技术验收 |

**重要节点数**：3

## 三、项目迭代进程（按五大方向，不含多人协作）

> 五大方向为本次持续优化的范围，**多人协作已从本迭代中移除**。下表将「方向」映射到具体小项目与建议阶段，便于按顺序推进。

### 3.1 五大方向与阶段映射

| 序号 | 优化方向 | 对应小项目 | 建议阶段 | 说明 |
|------|----------|------------|----------|------|
| 1 | **完善工具在无限画布的呈现**（Image / Video / Audio / …） | 项目 6 | Phase 2 能力 | 占位节点、Panel/Modal、事件桥、与 Grid 同步；Image → Video → Audio → Avatar 逐步接入 |
| 2 | **画布导航**：平移、缩放、Space、光标 | 项目 7 | Phase 2 能力 | 平移/缩放手感、Space 临时 Pan、光标与工具栏状态一致 |
| 3 | **画布基础交互完善**：多选、右键、快捷操作 | 项目 8 | Phase 2 能力 | 多选/框选、右键菜单、QuickAction、快捷键、批量操作 |
| 4 | **图层与层级管理** | 项目 12 | Phase 2 或 3 | Layers 面板、顺序调整、锁定/显隐、与 Grid 层级语义一致 |
| 5 | ~~多人协作~~ | 项目 13 | **本迭代不做** | 延后排期 |
| 6 | **UI 风格统一** | 项目 1、2、3、4 | Phase 1 必做 | Token → 侧边栏/底部栏 → 面板/弹窗 → 整体验收 |

### 3.2 迭代阶段与执行顺序

```
Phase 1：UI 风格统一（上线前必做）
├── 项目 1：Board 设计体系接入与 Token 统一
├── 项目 2：侧边栏与底部工具栏视觉统一
├── 项目 3：Canvas 面板与弹窗视觉统一
└── 项目 4：「两 view 同一产品」整体验收  ← 上线前里程碑

Phase 2：能力与交互（可与 Phase 1 收尾并行）
├── 项目 5：参考产品交互调研（weavy / tapnow / lovart）
├── 项目 6：完善工具在画布的呈现（Image / Video / Audio / Avatar）
├── 项目 7：画布导航（平移、缩放、Space、光标）
├── 项目 8：画布基础交互（多选、右键、快捷操作）
├── 项目 9：面板与弹窗动效与节奏
└── 项目 10：无障碍与性能

Phase 3：增强能力与上线后（视资源排期）
├── 项目 11：上线后 Board + Canvas 联合优化
├── 项目 12：图层与层级管理
└── 项目 14：历史与撤销（Undo / Redo）
```

### 3.3 建议的迭代节奏

| 迭代 | 重点 | 可交付 |
|------|------|--------|
| **迭代 1** | UI 统一基础 | 项目 1 完成（Token + 对齐清单）；可选启动项目 5（调研） |
| **迭代 2** | 框架与面板统一 | 项目 2、3 完成；项目 6 可启动（Image 完整链路） |
| **迭代 3** | 整体验收 + 画布手感 | 项目 4 验收通过；项目 7（导航）、项目 8（多选/右键/快捷）有可验收节点 |

| **迭代 5+** | 图层、历史、上线后联合优化 | 项目 12、14、11 按优先级排入 |
